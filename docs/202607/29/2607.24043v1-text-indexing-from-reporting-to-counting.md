## 摘要
我们证明了一个基本而强大的组合引理：在任何具有$L$个叶子的有根树中，深度小于其叶子后代数量的节点数至多为$L$。对于任意长度为$n$的字符串$T$，将该引理直接应用于$T$的后缀trie树可得，$T$中长度小于其在$T$中出现次数的子串数量至多为$n$。这一组合学洞见通过以下算法框架实现了具有最优查询时间的空间高效数据结构用于字符串计数问题：在预处理步骤中存储至多$n$个“频繁”子串的计数，并使用报告查询来计数“非频繁”子串。我们的框架作为一个便捷的黑盒，将报告时间为$\mathcal{O}(|P|+|\textsf{Occ}_T(P)|)$的索引提升为支持在$\mathcal{O}(|P|)$时间内完成计数查询，其中$P$是查询模式，$\textsf{Occ}_T(P)$是$P$在$T$中出现的集合。作为应用，我们展示了针对连续出现、加权序列、带效用字符串以及非重叠出现的高效索引。

## Abstract
We prove an elementary yet powerful combinatorial lemma: in any rooted tree with $L$ leaves, the number of nodes whose depth is smaller than the number of their leaf descendants is at most $L$. For any string $T$ of length $n$, a direct application of this lemma to the suffix trie of $T$ yields that the number of substrings of $T$ whose length is smaller than their number of occurrences in $T$ is at most $n$. This combinatorial insight leads to space-efficient data structures with optimal query times for string counting problems via the following algorithmic framework: store the counts for the at most $n$ ``frequent'' substrings of $T$ in a preprocessing step, and use a reporting query to count for the ``infrequent'' substrings. Our framework acts as a convenient black box, lifting indexes with reporting time $\mathcal{O}(|P|+|\textsf{Occ}_T(P)|)$ to support counting queries in time $\mathcal{O}(|P|)$, where $P$ is the queried pattern and $\textsf{Occ}_T(P)$ is the set of occurrences of $P$ in $T$. As applications, we show efficient indexes for consecutive occurrences, weighted sequences, strings with utilities, and non-overlapping occurrences.

## 1. 论文的核心问题与整体含义（研究动机和背景）

文本索引是计算机科学中的经典问题，广泛用于生物信息学和信息检索。传统索引主要支持两类查询：**报告查询**（返回模式 \(P\) 在文本 \(T\) 中的所有出现位置）和**计数查询**（仅返回出现次数）。后缀树可以在线性空间和最优查询时间内解决这两个问题（报告：\(O(m+|\textsf{Occ}_T(P)|)\)，计数：\(O(m)\)）。但许多现代索引（如压缩索引）只支持报告查询，而计数查询往往需要额外开销。论文的核心动机是**如何将任意报告索引“黑盒”地转化为支持最优时间计数查询的索引**，同时不显著增加空间。作者通过一个精巧的组合引理发现，文本中“长度小于出现次数”的子串数量至多为文本长度 \(n\)，从而使得预处理这些“频繁”子串的计数成为可能，其余“非频繁”子串可通过报告查询间接完成计数，达到整体最优查询时间。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心组合引理（Lemma 2.1）
- **引理陈述**：任何有 \(L\) 个叶子的有根树中，满足“节点深度 < 该节点叶子后代数”的节点数 ≤ \(L\)。
- **证明思路**：通过构造一个从这些节点到叶子的单射（取节点的第 (depth+1) 号叶子后代），利用叶子顺序和深度关系证明单射性。
- **字符串版本（Theorem 1.1）**：将引理应用于后缀 trie（每个内部节点对应一个子串），得到：字符串 \(T\) 中长度小于出现次数的子串数 ≤ \(n\)。该界是渐近紧的（Proposition 2.2）。

### 2.2 算法框架（Theorem 1.2）
- **输入**：一个报告数据结构 \(D\)，对任意模式 \(P\) 能在 \(O(m+|\textsf{Occ}_T(P)|+w)\) 时间内返回大小为 \(w\) 的答案。
- **构造**：
  1. 构建文本 \(T\) 的后缀树，并预处理每个节点的字符串深度和叶子数（即出现次数）。
  2. 标记所有“频繁”子串（对应节点满足深度 < 叶子数），最多 \(n\) 个。
  3. 对于每个频繁子串，使用 \(D\) 计算其答案并存储在后缀树的对应节点上；必要时将隐式节点显式化（增加最多 \(n\) 个节点）。
  4. 使用完美哈希支持后缀树上的 \(O(1)\) 边导航。
- **查询**：给定模式 \(P\)，在后缀树中定位其对应节点（\(O(m)\) 时间）：
  - 若节点已预存答案，直接输出（\(O(w)\) 时间）。
  - 否则，调用原数据结构 \(D\)，此时 \(P\) 为非频繁子串，满足 \(m \ge |\textsf{Occ}_T(P)|\)，总时间 \(O(m+w)\)。
- **空间**：\(O(|D| + w \cdot n)\)。
- **推论（Corollary 3.2）**：对于可分解为单元统计量聚合的问题（如求和、最大值等），进一步得到 \(O(n+s_{\text{Stat}})\) 空间和 \(O(m)\) 查询时间。

### 2.3 广义引理及更多应用
- **Corollary 1.3**（带参数 \(\tau\)）：满足 \(|U|\cdot \tau < |\textsf{Occ}_T(U)|\) 的子串数 ≤ \(n/\tau\)。用于将报告结构扩展到亚线性空间计数（如压缩索引）。
- **Corollary 1.4**（对称形式）：满足 \(|U| < \tau \cdot |\textsf{Occ}_T(U)|\) 的子串数 ≤ \(n\tau\)。用于内部模式匹配（IPM）模型中的计数。

### 2.4 高效构造算法（Section 7）
针对满足特定性质（如单元可分解、可 \(O(1)\) 查询局部统计量）的问题，提出 \(eO(n\sqrt{n})\) 时间的构造算法：
- **短子串**（长度 ≤ \(5\lceil\sqrt{n}\rceil\)）：直接遍历所有出现，总时间 \(O(n\sqrt{n})\)。
- **长子串**（长度 > \(5\lceil\sqrt{n}\rceil\)）：利用周期性（Lemma 7.4），将问题归约到文本中的“run”结构，通过预处理 run 的 Lyndon 表示实现快速查询。总时间 \(eO(n\sqrt{n})\)，空间 \(O(n)\)。

## 6. 论文的主要结论与发现

1. **组合引理**：有根树中深度小于叶子后代数的节点数不超过叶数，在字符串语境下转化为“长度小于出现次数的子串数 ≤ \(n\)”。该界渐近紧。
2. **通用黑盒框架**：任何报告索引（时间 \(O(m+|\textsf{Occ}|+w)\)）可转化为同查询复杂度的计数索引（时间 \(O(m+w)\)），仅需增加 \(O(w\cdot n)\) 空间。
3. **具体应用突破**：
   - **连续出现计数（COC）**：首次给出 \(O(n)\) 空间、\(O(m)\) 时间的计数索引（之前最优为 \(O(n\log n)\) 空间或更高）。
   - **带效用字符串索引（USI）**：从之前 \(O(n^2/\tau)\) 空间、\(O(m+\tau)\) 时间改进为 \(O(n)\) 空间、\(O(m)\) 时间，且构造时间从 \(O(n^2)\) 降至 \(eO(n\sqrt{n})\)。
   - **加权序列的统计查询**：在 \(O(nz)\) 空间内实现最优查询时间（如最重出现、平均概率）。
   - **非重叠出现计数**：得到紧凑索引（\(O(n\log\sigma)\) 位）与近最优查询时间，解决了文献中标注为“困难”的问题。
   - **内部模式匹配（IPM）模型**：给出空间-时间权衡的 USI 索引。
4. **广义引理**：导出了不同参数化版本，能处理压缩索引和 IPM 场景，拓展了框架的适用范围。
