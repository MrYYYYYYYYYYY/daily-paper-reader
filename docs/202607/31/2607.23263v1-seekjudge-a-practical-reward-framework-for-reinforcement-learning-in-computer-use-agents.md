## 摘要
判断一个轨迹是否真正完成了其指令，决定了我们如何在长周期图形用户界面任务中衡量计算机使用智能体，以及如何通过强化学习对其进行训练。长期以来，这种判断依赖于基于规则的评估，但规则评估难以与人类意图对齐，并且在应用更新或在线内容漂移时会变得过时。现有的基于模型的评判器试图解决这些问题，但与基于规则的评估相比仍存在性能差距。我们提出了SeekJudge框架，其中四个角色专用智能体——Condense、Ground、Seek和Analyze——通过一个对轨迹的Seek-Analyze循环来达成裁决。一条种子校准蒸馏流程训练一个专用的9B模型，作为所有四个智能体的共享骨干。以在保留的RL测试目标上的下游成功率来衡量，SeekJudge是第一个在在线RL中达到或超越原生规则监督的实用基于模型的奖励。除了准确性，SeekJudge还提供逐步判断，运行成本远低于闭源大模型，并保持较小的每次调用上下文，可扩展到更长的轨迹。我们还为奖励服务器贡献了一个通用的架构改进，可加速RL中的判断。这些共同使基于模型的奖励成为CUA强化学习中规则监督的实用替代品。

## Abstract
Deciding whether a trajectory actually fulfills its instruction governs how we measure computer-use agents on long-horizon graphical-user-interface tasks and how we train them with reinforcement learning. This judgment has long relied on rule-based evaluation, which struggles to align with human intention and goes stale when an app updates or its online content drifts. Existing model-based judges attempt to address these problems but still leave a performance gap to the rule-based evaluation. We propose the \textbf{SeekJudge} framework, in which four role-specialized agents, a Condense, a Ground, a Seek and an Analyze agent, reach a verdict through a Seek--Analyze loop over the trajectory. A seed-calibrated distillation pipeline trains one specialized $9$B model to serve as the shared backbone for all four agents. Measured by downstream success rate on held-out RL test goals, SeekJudge is the first practical model-based reward to match or surpass native rule-based supervision in online RL. Beyond accuracy, SeekJudge provides step-level judgments, runs far cheaper than a closed-source large model, and keeps a small per-call context that scales to much longer trajectories. We further contribute a general architectural improvement to the reward server that speeds up judging in RL. Together these make model-based reward a practical drop-in for rule-based supervision in CUA reinforcement learning.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想：定位与提取的解耦
- 将长轨迹判定分解为两个子任务：
  - **定位（Localization）**：找出持有决定性证据的步骤和截图。
  - **提取（Extraction）**：从单张截图中准确读出决定性细节。
- 与传统框架的多图单次前向传播不同，SeekJudge 用状态摘要做定位（选择图像 ID），用 Analyze 智能体做单图高保真提取。

### 2.2 四智能体框架（共享同一个 9B 骨干模型）
| 智能体 | 角色与职责 |
|---|---|
| **Condense** | 预处理器。对每一步读取动作前后两张截图，写出几行状态转换描述（T 条目），将整个轨迹压缩为紧凑文本时间线。 |
| **Ground** | 预处理器。对每一步读取动作后截图与原始动作（如 `click 128,453`），从截图中识别坐标实际命中的元素（A 条目），完成像素级动作接地。 |
| **Seek** | 控制器，是唯一跨轮次携带状态的智能体。读取 T+A 交错的时间线，判断累积证据是否足以裁决；不足时指定一个步骤和图像 ID，向 Analyze 发送聚焦问题，并将返回文本追加到上下文后进入下一轮。 |
| **Analyze** | 无状态提取器。每次调用只接收单张截图和一个聚焦问题，返回关键细节文本，相当于 Seek 调用的“工具”。 |

### 2.3 Seek–Analyze 循环流程
1. Condense 与 Ground 先将完整轨迹压缩为紧凑时间线；
2. Seek 智能体读取时间线，判断证据是否充分：
   - **充分** → 输出裁决：7 个轨迹级维度分数（0–100）+ 每步 9 类标签；
   - **不充分** → 指定单个步骤与图像 ID，向 Analyze 发送聚焦问题，接收回答后进入下一轮；
3. 循环直到证据充分或达到轮次上限。

### 2.4 输出与奖励映射
- **轨迹级**：7 个维度分数（正证据可靠性、负证据可靠性、目标不可行性、目标歧义、探索程度、路径冗余、完成程度），经梯度提升回归器（XGBoost）映射为标量分数，再设阈值得到二值判定。
- **步骤级**：9 类标签（里程碑、正确决策、纠错、中性、偏离路径、漏纠错、错误动作、无意义、虚假声明），映射为人工设定的常量，参与轨迹级奖励的塑形。
- **GRPO 奖励注入**：轨迹奖励 = 结果分数 + *w_step* × 步骤常量均值；组内相对优势为 (rᵢ − μ_G)/σ_G。注意步骤分数仅作为塑形项，不构成独立的逐步优势估计。

### 2.5 训练数据：种子校准蒸馏（Seed-Calibrated Distillation）
- **Seed 阶段**：人工标注约 20 条轨迹，通过 prompt 搜索（借助 Claude Code 迭代修订）使 DeepSeek 作为 Seek 智能体时对齐人类标签；再用 Codex + GPT-5.5 标注更大集合的进度描述，进一步校准 seek prompt。
- **Train 阶段**：用校准后的 prompt 运行完整 SeekJudge 流水线（DeepSeek V3.2 负责文本角色、Gemini 3.0 Flash Preview 负责视觉调用），记录每次智能体调用作为蒸馏数据，训练统一的 9B 模型。
- **数据规模**：约 1k 条种子轨迹、10k 条训练轨迹，覆盖网页、OS、Android 三平台，按任务难度采样，与所有下游基准和 OSWorld 目标零重叠。

### 2.6 工程优化：Rollout-Overlapped、零客户端状态奖励服务器
- **Rollout 重叠**：将不依赖后续动作的预处理操作（Condense、Ground）调度到环境执行动作的空闲 GPU 窗口内，只将短小的最终判定阶段留在关键路径上，减少 RL 训练阻塞。
- **零客户端状态**：RL 侧不保存奖励相关状态，仅乱序流式发送截图和动作；服务器负责重排序并异步调度预处理，RL 侧代码无需任何改动，是一种通用的多轮 RL 奖励服务器架构。

## 6. 主要结论与发现

1. **模型奖励首次匹配/超越规则监督**：在保留测试目标的下游成功率上，SeekJudge 是首个达到或超过原生规则监督的模型奖励。规则基线训练奖励最高，恰恰因为其训练信号就是评估指标本身，训练领先反映的是过拟合而非迁移能力。
2. **框架增益归因清晰**：在匹配的 Qwen3VL-8B 骨干下，SeekJudge 在三项离线基准的轨迹 F1 上均超过 OSThemis；训练后的 SeekJudge-9B 将轨迹 F1 提高 3.7–12.2 点（相对 Qwen3VL-8B 基础版），步骤级 F1 从 27.3 提升到 38.1。
3. **多图稀释机制明确**：竞争性内容（而非上下文长度）驱动性能下降——同 token 预算的纯噪声图不会损害甚至略微提升性能（红色曲线上升，与 Jang et al. 2025 的观察一致），而轨迹内其他截图导致模型倾向于接受轨迹（精度从 0.56 降至 0.45，召回几乎不变）。
4. **单前向评判器在长轨迹上两头失败**：小图像上限时关键截图常未被纳入（F1 随上限上升）；大上限时关键截图又被稀释（96 张图像时 F1 仅为 0.72，低于 SeekJudge 的 0.77）。
5. **计算量自适应任务难度**：工具调用次数随轨迹长度缓慢增长，控制器只复查对裁决有影响的步骤。
6. **奖励粒度影响 RL 效果**：连续分数 + 步骤级分数的稠密奖励取得最佳测试成功率（36.81%），优于 Boolean 版 SeekJudge（35.94%）和规则监督（30.43%）。
7. **组件均有贡献**：Condense 移除损失 4.1 点轨迹 F1/6.5 点步骤 F1；Ground 的像素接地和动作信息均有用；Seek–Analyze 循环的收益随骨干强度增长，在弱 8B 骨干上不显著，在闭源强模型和训练后的 SeekJudge-9B 上显著。
8. **步骤标签人类一致性良好**：254 步中 130 步落在精确对角线，159 步落在正确色块内——分歧主要来自块内细粒度区分，而非跨状态混淆。

2. **实用导向**：不满足于离线对齐，以“能否替代规则监督用于在线RL”作为最终判据，在多个端到端RL训练run中验证了模型奖励的实际可用性，而非止步于基准F1的提升。
3. **工程优化扎实**：Rollout-Overlapped调度、零客户端状态奖励服务器等设计，直接回应了“模型奖励太慢、无法用于RL”的经典质疑，且后者被视为通用的多轮RL奖励服务器架构，具有一定的扩展价值。
4. **严谨的归因实验**：通过在相同骨干上对比OSThemis排除了模型规模混淆；通过训练数据与评测基准零重叠排除了泄漏；通过多图/噪声对照实验排除了“上下文长度”这一替代解释，论证链条比较完整。
5. **数据建设贡献**：CUAStepBench 是首个覆盖六平台且同时具备轨迹级判定与密集事后步骤标签的CUA奖励基准，CUAStepBench-Long 填补了长轨迹（平均272步）奖励评估的空白，对社区后续研究有参考价值。
6. **成本意识强**：不仅报告准确率，还系统报告了推理成本与峰值上下文占用，且在多个图像数量下均保持最低成本，使“实用奖励框架”名副其实。

## 8. 局限性与不足

1. **训练数据对闭源模型的依赖**：种子校准蒸馏依赖 DeepSeek、Codex、GPT-5.5 等闭源模型生成标注，完整流水线的开源可复现性有限；训练后开源的仅 9B 小模型，其表现与闭源驱动时存在差距。
2. **步骤级信号质量仍偏低**：步骤级 F1 从 27.3 提升至 38.1 后仍有较大提升空间，且步骤标签主要来自模型蒸馏（人工验证仅覆盖 254 步），作为 RL 塑形信号的可靠性尚需进一步验证。
3. **RL 验证规模有限**：在线 RL 实验仅覆盖 Chrome、Impress、OS 三个任务域，每个应用单独训练一个策略；未在 Windows、macOS、Android、iOS 等更广泛平台上验证 SeekJudge 奖励的训练效果。
4. **统计显著性缺失**：离线基准与 RL 结果大多只报告均值（虽附运行间标准差），未对 SeekJudge 与规则监督、OSThemis 等关键对比做正式的显著性检验；个别对比（如训练后 SeekJudge-9B  vs  Qwen3VL-8B 基础版）差异在 3.7–12.2 点之间，是否稳健仍需更多运行支撑。
5. **校准泄漏探测的间接性**：附录 B 用三基准交叉拟合验证回归器无过拟合，但 RL 使用的拟合参数与离线评估不同（排除目标级维度），该差异对训练效果的直接影响未见专门消融。
6. **长轨迹基准规模过小**：CUAStepBench-Long 仅有 18 条轨迹，图 9 中 SeekJudge 与 CUAJudge 的差异（0.77 vs 0.72）在如此小的样本上是否统计可靠存疑。
7. **多图稀释机制的解释限于小规模**：图 6 的竞争性内容解释基于 123 个可单图判定案例，规模偏小；且“加入轨迹图像导致模型倾向于接受轨迹”这一现象是否在所有骨干上普适，未做跨模型验证。

---

## 9. 综合评估

总体而言，SeekJudge 在**问题定义**（定位 vs 提取的解耦）、**方法论**（四智能体协作 + 种子校准蒸馏）、**实验设计**（多基准离线评估 + 多骨干在线 RL + 系统消融）三个层面均达到较高水准，其核心主张“模型奖励可以在在线 RL 中达到甚至超越规则监督”有充分证据支撑，对 CUA 领域从规则评估向模型评估的转型具有实质推动意义。

但论文在**训练数据独立性**（依赖闭源模型蒸馏）、**步骤级信号可靠性**、**统计显著性报告**以及 **RL 验证覆盖范围**上仍有明显不足，距离“即插即用、完全开源可复现”的通用奖励框架尚有一段距离。未来工作如能扩大长轨迹与多平台 RL 验证、引入更细粒度的人工步骤标注、并解决开源模型自举（self-bootstrapping）条件下的标注质量，该框架的实用价值将更为稳固。

---

**一句话总结**：SeekJudge 通过“定位—提取”解耦与多智能体协作，首次证明了模型奖励在在线 CUA 强化学习中能替代原生规则监督，工程设计与实验论证俱佳，但在统计严谨性与推广验证上仍有提升空间。
